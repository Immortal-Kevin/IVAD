# P3 数据集管理操作指南（生命周期版）

更新：2026-10-16。仅源码版，Schema0009；PACKAGING_FREEZE = TRUE。关闭旧源码窗口后通过“启动IVAD.cmd”重启。首次打开旧项目时程序先备份SQLite，再执行增量迁移；不使用旧Beta包打开已升级项目。

## 1. 选择图片

**目的：** 找到当前项目、摄像头的合格人工样本。

**步骤：** 项目管理打开正确项目→数据集管理→图片列表与筛查。选择摄像头、故障、处理结果、来源等条件。点击“全选当前结果”“全选正常”“全选异常”或逐项勾选。可按时间/摄像头/类别排序，悬停查看UUID、来源和校验详情。

**正常结果：** 全选仅勾选当前可见且合格的检测候选；正常无框合法，异常必须有合法目标。未知、冲突、剔除或仅整帧异常无框不能自动入Detection。显示候选/已选/正常已选/异常已选数。

**常见问题：** 勾选不是已加入草稿。Tab切换保留勾选；主动修改筛选会清空勾选，草稿成员独立保留。时间列是当前媒体相对秒，原PTS及片段原视频相对时间在详情，不是摄像头拍摄日期。

## 2. 创建并保存数据集草稿

**目的：** 让数据集身份和成员持久保存，退出后可恢复。

**步骤：** 切换“新建数据集”→选择“创建新数据集”→输入名称→核对所属项目（来自项目管理）→选择目标摄像头、勾选目标故障类型，任务为Detection→“添加所选图片”→检查成员明细→点击“保存数据集草稿”。同图多个故障目标必须明确勾选全部对应类别，不会静默丢弃其他目标。正常帧引用不会因此被赋予故障标签。

**正常结果：** 保存成功显示实际保存时间及Dataset UUID。一个摄像头可建多个不同故障数据集，名称不是主键，Dataset UUID稳定。多个数据集可引用同一正常图而互不改写标注。

**常见问题：** 多摄像头共享须明确勾选授权；新建另一个数据集会重置共享及工程划分授权。修改名称、成员、摄像头/故障或划分设置会显示“未保存修改”，先前检查失效。保存失败保留内存内容。当前采用手动保存，没有防抖自动保存；退出或切换数据集/项目时可选择保存、放弃或取消，强制结束进程不能保证恢复未保存内容。

## 3. 重新打开、编辑与移除

**目的：** 恢复已保存草稿并继续处理。

**步骤：** 重启软件→打开同一项目→数据集管理→新建数据集Tab→在数据集下拉框选择原名称和UUID短码。核对成员数量、摄像头、故障类型和保存状态。需要移除时到图片列表勾选成员，再点“移除草稿中所选图片”；也可清空当前草稿，再保存。

**正常结果：** 已保存成员和Annotation UUID引用恢复，重复添加显示重复跳过，修改再次保存仍使用同一Dataset UUID。其他数据集和已有冻结版本不变。

**常见问题：** 筛选只是列表视图，不能代替数据集选择。旧冻结数据集也能在下拉列表找到；其历史版本可查看/导出，继续编辑前需明确配置并保存新草稿，不自动猜旧草稿。旧版只在内存中的草稿无法从空数据库恢复，需要重新选择现存图片并保存；原图片和标注没有丢失。

## 4. 自动划分并检查

**目的：** 给已保存草稿生成可追溯的训练/验证/测试方案。

**步骤：** 保存前先在“训练集划分设置”选择预设，再回到新建数据集保存。Tab顶部始终显示Dataset名称/UUID、项目、摄像头、故障、成员和状态。保存后点击“自动划分并检查已保存草稿”。未选数据集或尚未保存时操作禁用。

| 预设 | 目标比例 | 用途 |
|---|---|---|
| 标准训练（推荐） | 70/20/10 | 优先完整原视频来源组，不拆相关片段 |
| 小样本实验 | 80/20/0 | 管线验证；没有独立Test，不作最终泛化结论 |
| 自定义（高级） | 用户设置，合计100% | 展开比例、分组和Seed；默认隐藏复杂输入 |

**正常结果：** 系统按实际来源组大小、正常/异常及类别分布尽量接近比例。表格分开显示图片数、目标数、正常/异常、原视频组及泄漏状态；实际比例可偏离目标，不为凑数拆组。Seed默认123，用于复现，不是训练轮数。每次检查重新验证文件、标签、坐标、引用及来源。

**常见问题：** 当前8525的200张来自同一个原视频。标准策略会得到200/0/0并LIMITED，需要补充独立录像才能形成独立验证。若仅验证工程管线，可选择小样本，并明确勾选“允许隔离工程图片划分”和“允许LIMITED隔离实验”，保存后重新检查；仅在来源组不足时才启用带泄漏风险的工程随机方案。相邻帧不能当独立工业验证。BLOCKED必须解决问题后重新保存/检查；VALIDATED表示结构检查通过，不等于独立性PASS或生产批准。日期/工况分组及手动拖动分组当前不支持。

## 5. 冻结版本

**目的：** 把检查通过的保存修订固定为不可变快照。

**步骤：** “数据集版本”Tab核对当前Dataset UUID、草稿状态和数量→“检查并冻结新版本”→确认→等待任务成功。LIMITED需已明确接受工程用途。没有版本时页面有明确提示。选择历史版本可检查文件完整性/来源或导出YOLO Detection等格式。

**正常结果：** 自动生成该Dataset的v1/v2…，保存图片、标注、类别映射、实际划分、来源、草稿修订/检查签名及哈希。后续草稿修改不会改变旧版本。正常空检测标签、多边形外接框与原生旁车规则保持。

**常见问题：** 保存不是冻结，草稿不能直接作为训练输入。冻结前再次检查当前保存修订及源数据；过程发生修改会拒绝提交。文件缺失/冲突/未知/剔除等阻断错误不能正常冻结。不同版本含同一图片也有各自不可变快照，避免历史内容被新标注静默覆盖。

## 6. 供AI训练选择

**目的：** 明确选择Dataset与DatasetVersion。

**步骤：** AI训练→所属数据集→冻结数据集版本→模型架构与参数→训练前检查。保存草稿但没有冻结、或只有Train没有Val的版本，不会进入可训练版本列表。实际启动仍需已有的NVIDIA GPU检查。

**正常结果：** 训练记录保留Dataset UUID和Version UUID，模型可追溯。同一冻结版本可以供YOLO26n/YOLO11n比较；本次修复没有重新训练。

**常见问题：** 下拉列表只提供Train/Val非空、清单可校验的冻结版本；启动前仍做完整图片/标注/来源校验。LIMITED实验不能用于生产性能认证，生产注册仍需独立人工批准。本轮没有报警、预标注、部署或软件打包。

## 候选排除与全局剔除

“从候选列表排除”仅影响当前会话的候选显示，并从当前草稿移除成员；要持久保存成员变更须点保存。“恢复候选排除”不自动重新加入草稿。该候选隐藏集合仍不跨重启保留。全局“标记所选为无效帧/恢复已剔除图片”沿用原软状态服务、确认与历史；管理恢复可逐项勾选，训练全选不会勾选剔除图。没有永久物理删除功能。

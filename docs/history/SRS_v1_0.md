# IVAD Platform v1.0 — 软件需求规格书（SRS）

- 文档版本：1.0.0 / 需求基线
- 日期：2026-10-12
- 状态：十项产品决策已确认；工程实现与硬件性能尚待验证
- 产品：Industrial Visual Anomaly Detection Platform（IVAD Platform）
- 语言：界面、帮助、报告默认简体中文；内部标识符与代码优先英文

## 1. 目的与边界
IVAD 是一体式工业视觉异常检测平台。全部日常操作经**同一 GUI**完成，无需操作者编辑代码/配置。产品提供**开发工作空间**（数据、标注、训练、验证、模型仓库）和**生产监控工作空间**（离线录像检测、报警规则、事件复核），共享项目与统一服务层。第一版以 Windows 11、Intel Core Ultra X7 358H、Intel Arc B390 iGPU、32GB RAM 为优先验收环境。架构兼容 NVIDIA GPU，但后续另行实机验收。

**交付边界**：本地离线 v1.0 为必须交付；RTSP、局域网服务器计算、PostgreSQL、多客户端、生产 PLC 联动属于预留/后期阶段，不能宣称已实现。禁止 v1.0 自主向 PLC 下发控制命令。

## 3. 用户、场景与验收原则
- 用户：初期为一名技术人员，未来可扩展工程人员、审核员、生产操作员。v1.0 可采用单用户本地身份，不需预先完成企业 IAM。
- 场景：厂区交付 MP4/AVI/MOV/MKV → 本地视频导入 → 抽帧 → 人工标注与审核 → 点击训练 → 验证发布 → 用新录像推理 → 报警证据与人工反馈。
- 非目标：没有现场视频不承诺故障检测准确率；不因某模型 COCO 基准表现而假定选煤厂有效；不使用模拟检测结果作为生产结论。

## 4. 功能需求（FR，M=本地 v1.0 必需；R=接口/结构预留；F=未来实现）
### 4.1 项目与统一 GUI
- FR-001 [M] Windows 原生统一桌面应用；开发和生产两个工作空间，含导航、任务状态、中文错误反馈和日志入口。
- FR-002 [M] 项目含厂区/设备/摄像头的可选关联，支持创建、保存、打开、归档、复制与导入导出。
- FR-003 [M] 后台耗时作业不得阻塞 GUI；可暂停/取消的任务按实际能力标示；状态跨重启保存。
- FR-004 [M] 未开发功能须明确“不可用/规划中”，不得设置假动作按钮。

### 4.2 视频管理与抽帧
- FR-010 [M] 视频导入支持 MP4/AVI/MOV/MKV 的常见编码；不保证所有封装/编码组合；报告解码错误原因。
- FR-011 [M] 复制或外部引用，默认复制；去重基于文件校验值；引用丢失时可重新定位。
- FR-012 [M] 记录宽高、帧率、时长、时间基、帧/时间戳、哈希、来源路径及摄像头；允许 VFR 及旋转元数据；禁止仅靠 frame_index/FPS 推算全部时间戳。
- FR-013 [M] 固定间隔、指定时段密集抽帧、按画面变化/相似度去重，预览后批量确认；任务可重试与幂等。
- FR-014 [M] 已有兼容模型且审核允许时进行 AI 辅助候选帧筛选；不得把未标注或模型未检测到的帧全部判为正常。
- FR-015 [M] 抽取帧对原视频、PTS 时间、采样策略和图像变换保持可追溯。
- FR-016 [R] 统一 VideoSource 接口适配文件与 RTSP；流重连/多摄像头属于 [F]。

### 4.3 标注与数据集
- FR-020 [M] 图像矩形框、Polygon/Mask、固定摄像头 ROI、整帧标签、时间片段标签，按 P2 实现顺序交付；同一画面可多个实例与类别。
- FR-021 [M] 分类/故障标签可在 GUI 新增、编辑、弃用；ID 稳定；修改类别不得静默破坏旧训练集。
- FR-022 [M] 画布缩放/平移/撤销/重做/自动保存；所有显示坐标转换为原始图像坐标并测试精度。
- FR-023 [M] 明确标注状态：未审核、已确认、拒绝、待补充；区分人工标注与 AI 建议；每次修改有来源与时间。
- FR-024 [M] 负样本、未知/无法判断与未标注样本必须区分，禁止自动当作等价。
- FR-025 [M] 可导出 YOLO detect/segment 和必要 COCO 格式（仅对适用标签）；视频时间标签保留独立规范，不能强行伪装为目标框。
- FR-026 [M] 数据集不可变快照、版本、清单及哈希；按源录像/时间段/摄像头分组划分训练/验证/测试，防相邻帧泄漏。

### 4.4 模型、训练与 GPU
- FR-030 [M] ModelAdapter/Detector 接口区分 detect、segment、temporal、rule 类型；单一模型多类与多个专用模型组合。
- FR-031 [M] 默认主模型选择须基于 P0 中 YOLO26n、YOLO11n B390 实测；不是凭最新发布日期定优先级。
- FR-032 [M] 模型能力矩阵按版本明示：import、infer、train、validate、export，不得声称“所有 YOLO 均可训练”。
- FR-033 [M] 简易与高级 GUI 训练；用户设定数据集、设备、epochs、batch、imgsz 等；任务预检、进度、日志、指标、取消和检查点。
- FR-034 [M] 实验→候选→生产，验证符合项目设定门槛后需人工批准发布；生产只能使用批准版本；支持原子切换和回滚。
- FR-035 [M] 自动检测计算设备并可人工指定；Intel 推理优先 OpenVINO GPU，训练验证 PyTorch XPU；NVIDIA CUDA 后端作为独立适配器及未来实机测试项目。
- FR-036 [M] 模型**前向、后向、权重更新、推理计算**禁止 CPU-only 后端或隐式 CPU fallback；CPU 可负责视频解码、预处理、数据加载、GUI、日志、规则判断。后端不可用时任务失败并明确告知。
- FR-037 [M] 保存训练权重、推理工件、class map、输入尺寸、前/后处理、运行库版本、许可与模型来源；跨设备转换后重新验证输出一致性。
- FR-038 [M] 智能 GPU 任务排队，避免单 GPU 训练与生产推理争用；远期多 GPU 与生产任务优先级 [R]。

### 4.5 推理、规则、报警、复核
- FR-040 [M] 对新录像逐帧/抽样推理，可配置 ROI、显示检测框/掩膜、时间轴和进度；支持回放。
- FR-041 [M] 告警规则每设备/摄像头/故障可配置：分数、ROI、连续帧、持续时长、严重级、冷却、去重；单帧检测与最终事件独立记录。
- FR-042 [M] 基于视频 PTS/实际时间进行时序判断；对掉帧、漏检、视频跳转、帧率变化明确处理；避免把逐帧重复识别当多个报警事件。
- FR-043 [M] 事件包含项目/摄像头、故障类型、模型与规则版本、时间戳、分数、坐标/ROI、审查状态及不可变关联引用。
- FR-044 [M] 保存原始截图、叠加截图、前后可配置视频证据、检测原始数据及审查记录；允许视频证据生成失败但事件须保留并标注缺失。
- FR-045 [M] 复核操作包括确认、误报、无法判断、补标/漏报，形成候选标注池；仅用户启动训练，不在线自动改变生产权重。
- FR-046 [R] 与 RTSP 的流输入相同推理/告警接口；实时 SLA、摄像头同步与重连 [F]。无 PLC 输出。

### 4.6 存储、接口、迁移
- FR-050 [M] SQLite 存储结构化元数据；视频/图片/模型/证据用文件，数据库索引和哈希；使用数据访问抽象层。
- FR-051 [M] 外部引用与项目相对路径明确区分；迁移/备份检查源文件缺失，复制完整项目时可选包含外部源视频。
- FR-052 [M] API-Ready 内部服务契约：Projects/Media/Annotations/Datasets/Models/Jobs/Events/Devices；版本化请求响应和错误码。
- FR-053 [R] PostgreSQL 适配/迁移；FastAPI + 鉴权 + LAN 客户端 [F]；v1.0 不暴露无认证网络监听端口。
- FR-054 [M] 数据库备份恢复、模型原子发布、写入一致性、任务失败重试/幂等，删除前依赖检查。

## 5. 非功能要求（NFR）
- NFR-01 离线优先：日常工作不依赖互联网；首次安装/下载模型可经用户批准联网。
- NFR-02 GPU-only AI：必须有真实后端验证证据，不能以设备枚举成功替代推理/训练实测。
- NFR-03 安全隔离：不得改动其他 AI 项目、系统驱动/代理/全局 Python；独立依赖环境；用户批准后才允许系统级变更。
- NFR-04 可维护性：Python 类型、模块隔离、结构化日志、中文错误对照、自动测试、固定版本、变更记录。
- NFR-05 数据完整性：标注原子持久化、文件哈希、迁移校验和版本追溯；对硬中断的最后未提交操作不作绝对零丢失承诺。
- NFR-06 本地安全：处理路径穿越、恶意压缩包、模型反序列化风险；仅导入可信 `.pt`，优先校验可信来源与安全交换格式；不允许未经授权执行下载模型带来的脚本。
- NFR-07 隐私：工业摄像头文件保持本地；日志默认不记录敏感视频内容；网络/遥测默认关闭。
- NFR-08 打包：源代码及 Windows 安装包，目标机需满足厂商驱动与 GPU 运行时要求；不能保证任意硬件零依赖安装。
- NFR-09 性能：P0 记录 B390 真实 FPS/时延/峰值共享内存/运行稳定性；无工厂样本时不设虚假工业准确率承诺。
- NFR-10 许可：在商业/闭源/厂内生产场景使用 Ultralytics 相关代码和权重前评估 AGPL-3.0/Enterprise 条款；许可证未获解决不得宣称生产可商用。

## 6. 安全与可靠性原则
- 漏报、误报和数据漂移属于模型与场景风险；采用跨录像/跨摄像头测试与人工审核。
- 生产告警只提供辅助决策；不能直接触发输送机/破碎器控制；厂区控制联动需独立风险评估与安全联锁。
- 不可用 GPU、视频文件断链、损坏模型、数据库错误必须界面可诊断；生产版本不得因为测试模型更新而变化。

## 7. 阶段与验收追踪
| 阶段 | 交付 | 关键验收 |
|---|---|---|
| P0 | Intel B390 环境与基准报告 | 真实 XPU/OpenVINO GPU 推理、反向传播及小样训练可行性；双 YOLO 对照；失败明确记录；无系统破坏 |
| P1 | 项目骨架与统一 GUI | 双工作空间、项目/设置/任务/日志和 SQLite 基础运行；未实现功能诚实标识 |
| P2 | 视频与标注工作台 | 导入/复制引用、固定与变化抽帧、多形式标签、自动保存、数据集导出与追溯 |
| P3 | GUI 训练与模型仓库 | 已支持模型 GPU 训练或明确阻断、版本状态、验证、人工发布、回滚 |
| P4 | 离线推理及报警 | 新录像识别、规则计算、证据生成、人工审核、模型/规则追溯 |
| P5 | AI 辅助标注与反馈 | AI 建议与人工确认区分、候选队列、训练集再版本化，不自动替换生产模型 |
| P6 | 集成、恢复、打包 | 端到端、备份恢复、环境隔离、Windows 安装包与中文操作说明 |

阶段验收由用户授权进入下一阶段。每阶段记录 PASS/FAIL/NOT TESTED/BLOCKED；报告提供重现方法、系统信息和风险。

## 8. 尚需实测与后续决策
1. B390 PyTorch XPU + 当前 Ultralytics 的实际 YOLO26n/YOLO11n train 兼容性；必要时以模型级小样训练区分前后向支持与框架集成缺陷。
2. B390 OpenVINO GPU 模型导出、精度对齐、FPS、CPU/GPU 实际占用；CPU 仅允许非 AI 计算职责。
3. 错误率、漏报率、响应时延及证据窗口阈值，在厂区真实录像上确定。
4. Windows 安装包类型与驱动先决条件在 P6 决定；商业授权在生产部署前完成评估。

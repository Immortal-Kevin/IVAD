# 通用源码与私有工业资产边界（拟议，未实施）

日期2026-10-19。用户新目标允许评估部分开源，但未授权实际发布、改变已有授权或转让版权。本报告不改动既有LICENSE_POLICY/专有授权草案，后者作为历史方案保留。著作权人须先确认职务/委托/合作贡献链，再批准具体模块与许可证。

## 当前风险与证据

本地存储不是充分保密措施。当前SQLite、权重、数据集/模型导出和缓存主要靠本机文件权限；SHA用于完整性，不能加密或阻止复制。未验证磁盘加密、密钥管理、最小ACL、角色鉴权、导出审批、恢复演练或安全擦除，不能称已具备这些能力。

实际 `ProjectStore` 可打开项目目录，`SettingsService.remember`保存真实最近项目路径；数据集Native/COCO旁车携带来源和标注，ModelService.export复制权重/ONNX和完整details，含训练参数/类别及关联信息。`LoggingService.redact`及`diagnostic_export.scrub`有路径/凭据脱敏，但不覆盖所有商业秘密、自由文本、图像与模型。诊断ZIP、错误栈、Worker日志、缓存manifest、临时导出和Windows崩溃转储均应按敏感资产处理；模型导出SHA不代表获得导出授权。

Git可达历史扫描37提交/661blob，当前9张已追踪界面截图及报告/测试中的真实项目引用，详见 `licenses/p37l/GIT_HISTORY_SCAN.json`。`.gitignore`没有全面覆盖`.pth`、`.ckpt`、真实JSON/YAML/CSV配置；且ignore不能保护已追踪/强制加入的截图。**禁止把当前仓库或完整历史直接推到公开远程。** 本轮没有删除资产、改历史或修改ignore。

模式扫描154条“blob/类别”候选，包含重复版本和普通示例，不等于154个泄露事件；未匹配长字面量凭据规则不代表没有秘密。必须补人工/图像OCR、业务参数语义、不可达/仅reflog对象、LFS与外部备份扫描。现存作者邮箱和路径也须公开前处理，不在本报告复述值。

## 拟议分层

| 层 | 可公开内容候选（须产权/许可审查） | 必须私有内容 | 接口与控制 |
|---|---|---|---|
| Public UI/Core | 通用Widgets布局、任务状态机、标注画布、视频时间/抽帧算法、Adapter协议、通用告警接口和格式规范 | 实际厂区名称、设备类别表、摄像头清单、生产参数、规则实现中的商业秘密 | UI通过通用接口请求资源，不附真实默认配置；示例使用合成数据 |
| Asset service | 数据接口定义、通用错误码、权限声明/审计事件格式 | 视频、图片、标注、实际SQLite/PostgreSQL、草稿/冻结集/所有导出 | 资源服务按用户/项目鉴权，不只靠知道路径或UUID；公开接口不等于匿名可读 |
| Model boundary | 通用预测输入/输出、模型能力/版本协议、完整性验证逻辑 | 工业权重、Checkpoint、ONNX、Registry数据、训练来源与私有超参 | 最小权限加载；校验、授权和导出三者分别执行；推理API限流/审计，防批量提取 |
| Private domain modules | 可公开抽象扩展点 | 实际ROI、设备映射、阈值、时序持续/冷却/级别、私有规则业务模块、服务器与通讯配置 | 版本化协议、数据最小化；法律上是否独立作品须另审，进程边界本身不是copyleft豁免 |
| Operations | 无敏感值的部署模板、合成测试、依赖与许可说明 | 密钥/Token、真实地址、日志/转储、缓存、备份、升级/签名密钥 | 凭据用OS凭据库/受控secret store，禁入源代码、命令行、明文日志和公开样例 |

拟议目录：公共代码仓库仅含人工批准的文件白名单；真实数据库和模型置于代码目录之外的`<private_root>/projects`、`models`、`config`、`cache`、`backup`。这些是设计占位符，不是本轮新建或迁移。通用数据库schema可评估公开，体现商业规则的部分需单独隔离；数据表结构与实际数据不是同一资产。

## 必须落实的控制（均未实施验收）

1. 发布采用新建、无历史的经过批准的公共快照；不改既有私有Git历史。默认拒绝所有文件，只允许经许可/秘密扫描的通用源码；排除报告、截图、artifacts、数据库、权重、真实夹具及参数。扩展名黑名单只是补充。
2. 公共测试用独立合成视频/图像/标注与虚构地址、类别；当前依赖真实冻结集的验收用例保留私有，不直接公开。
3. 对仓库、工作区、导出、缓存、临时目录、崩溃转储、日志和备份分别制定ACL/保留期与删除审批。系统管理员或拥有密钥的运行主体仍可能读取进程内模型，不能承诺技术上绝对不可复制。
4. 私有模型使用最小ACL、加密存储/磁盘、密钥轮换与离线备份、SHA和版本旁车，按策略做可恢复验证；完整性校验不替代访问控制。
5. 数据/权重导出需权限校验、审批、接收人和用途审计；敏感来源/参数默认最小化，按权限提供完整溯源。不得因GUI开源就放开导出。
6. 未来LAN API用认证、项目级RBAC、TLS、短期凭据、最小绑定地址、审计和流量控制；不在当前产品中声称已存在FastAPI/Uvicorn或鉴权。
7. RF Worker已有HF_HUB_DISABLE_TELEMETRY/DO_NOT_TRACK、TensorBoard关闭和本地权重检查，但这不是无外联证明。另行批准后对缺失缓存/下载、Hub/MLflow/W&B等可选路径做禁止外联测试与网络策略，禁传图像/权重/参数。
8. 未来更新只发布代码与经许可运行库，使用签名/回滚；不把数据/模型备份塞入更新包，不给更新器默认上传日志/转储权。LGPL库替换权与私有资产访问控制可并存，不能用反修改条款抹掉适用库权利。

## A / B方案比较

| 事项 | A：自研代码闭源 | B：通用框架部分开源、资产/业务私有 |
|---|---|---|
| 免费许可路线 | Apache/MIT/BSD+经履约LGPL，排除不适用GPL/AGPL组合 | 同样需逐组件履约；公司仅给有权许可的独立通用代码选许可证 |
| Qt义务 | 动态链接、通知、对应源码与兼容替换/调试权仍要做 | 开GUI不能免Qt源码/通知、GPL-only模块及二进制义务；可能方便审计和重链接 |
| Ultralytics | 正式闭包排除，历史权重争议另审 | 只开GUI不是整个AGPL衍生工作的许可解决方案，更不能据此认定旧权重/私有业务当然可保密 |
| 架构量/工程估算 | 资产外置、ACL/导出边界、最小payload；约5–10人日，需授权和测试 | A基础上做产权/来源切分、白名单/合成夹具、独立公共快照；约8–15人日；仅粗估、不含法务/codec回归 |
| 维护 | 私有发行及第三方履约由公司维护 | 双边界/接口版本、公共漏洞修复与私有规则兼容的维护更多 |
| 保密风险 | 交付安装包/日志/模型导出仍可能泄密 | 误公开Git历史/真实夹具/配置风险更高；开源许可不提供数据访问控制 |
| 关联厂区共享 | 按实体和副本/运行库交付履约；数据协议另签 | 公开代码可分发不等于可共享工业数据；私有业务是否衍生、接收方条件仍审 |

Apache §2–4仅适用于其覆盖的作品，不自动更改其他组件；LGPL/GPL/AGPL对组合/衍生范围有不同要求。权重是否含受许可内容、输出是否构成covered work以及模块独立性存在事实与法域判断，须LEGAL REVIEW，不靠“插件/微服务”命名直接作结论。[Apache](https://www.apache.org/licenses/LICENSE-2.0)、[AGPL §2/5/13](https://raw.githubusercontent.com/ultralytics/ultralytics/v8.4.176/LICENSE)、[Qt义务](https://www.qt.io/development/open-source-lgpl-obligations)。

## 2. P2 核心交付目标

P2 完成后，用户必须能通过同一个 IVAD GUI：

1. 打开已有选煤厂项目。
2. 批量导入监控录像。
3. 播放视频、暂停、拖动时间轴和逐帧定位。
4. 自动提取视频元数据。
5. 通过固定间隔或画面变化方式抽帧。
6. 从视频时间轴选择异常时间段并加密抽帧。
7. 浏览生成的候选图片。
8. 人工绘制矩形框、多边形和 ROI。
9. 给图片和视频片段添加故障标签。
10. 保存、修改、删除和重新打开标注。
11. 自定义故障类型。
12. 组织并冻结数据集版本。
13. 导出兼容的 YOLO Detection、Segmentation 数据集及通用标注格式。
14. 关闭软件后重新打开，所有项目数据与标注仍然存在。

上述操作必须实际可运行，不允许只制作静态页面或无功能的按钮。

## 3. 视频导入与媒体管理

### 3.1 输入视频

优先支持：

- MP4
- AVI
- MOV
- MKV

利用 FFmpeg/ffprobe 或经验证的视频处理库读取实际编码信息。

不要根据扩展名直接断言文件可解码。

支持 GUI 批量导入、导入进度、导入失败提示。

### 3.2 原始文件存储策略

按已确认的 SRS，实现两种方式：

A. Copy Mode：复制原始录像到项目存储目录。

B. Reference Mode：仅保存外部文件引用。

默认使用 Copy Mode。

要求：

- 复制前检查磁盘空间。
- 不覆盖同名文件。
- 使用 UUID 或内容校验值管理资产标识。
- 对重复视频给出提示。
- 保存原始路径及当前可访问路径。
- 保存文件大小和 SHA256。
- 导入中断时不得留下被标记为完整的损坏资源。
- Reference Mode 文件丢失时，在 GUI 中显示 Missing，不得删除数据库记录。
- 不擅自修改或删除原始录像。

### 3.3 媒体元数据

记录：

- Media UUID
- 项目 UUID
- 原始文件名
- 文件路径或引用方式
- 文件哈希
- 视频时长
- 视频宽高
- 标称帧率及实际时间戳信息
- 编码格式
- 创建/导入时间
- 摄像头编号（可选）
- 厂区、设备信息（可选）
- 解码状态

如无法从视频元数据确定真实拍摄时间，不得将文件创建时间当成确定的摄像头拍摄时间。

## 4. 统一视频播放器

在 P1 开发工作空间中实现真实的视频播放器。

要求：

- GUI 内嵌播放。
- 播放和暂停。
- 可拖动时间轴。
- 显示当前位置与总时长。
- 逐帧前进和后退。
- 自定义播放速度。
- 指定时间位置跳转。
- 显示实际画面分辨率。
- 从当前画面创建候选标注帧。
- 选择起止时间形成视频片段标签或抽帧范围。

优先评估 PySide6 Qt Multimedia 与 FFmpeg 的实际兼容性。

播放器和抽帧器必须遵循一致的媒体时间戳定义。

要正确处理：

- 可变帧率视频。
- 非整数帧率。
- B 帧与帧重排序。
- 视频跳转后的实际帧定位。
- 视频旋转元数据。
- 异常或缺失时间戳。

如 Qt 播放器存在有限精度或不支持某种编码，需显示限制并提供明确提示。

不得伪称所有 AVI/MP4 编码均已兼容。

## 5. 自动抽帧引擎

本阶段实现两种真实抽帧方法，并预留第三种 AI 辅助方法。

### Mode A：Fixed Interval

支持 GUI 设置：

- 每 N 秒抽取一帧。
- 自定义起止时间。
- 限制最大候选图片数。
- 输出图像格式。
- JPEG 质量设置。
- 原始分辨率保存或选择缩放。

默认不能未经用户确认生成无限数量的帧。

### Mode B：Smart Sampling

利用画面差异、相似度或运动变化进行候选帧筛选。

要求：

- 提供可理解的敏感度设置。
- 不把画面变化直接等同于工业异常。
- 允许人工审核筛选结果。
- 支持保留固定间隔基础样本。
- 支持正常画面与异常候选混合采样。
- 避免算法将少量关键异常全部去除。

### Mode C：AI-Assisted Sampling

本阶段只定义接口和 GUI 中的未来功能入口。

无已发布可用模型时，必须显示 Not Available。

不得借助 CPU 推理来假装实现 AI 辅助抽帧。

完整 AI 辅助筛选与自动预标注将在后续 P5 实现。

### 后台任务要求

全部抽帧任务必须复用 P1 Job Manager。

支持：

- 后台执行。
- 进度显示。
- 用户取消。
- 错误日志。
- 任务历史记录。
- 应用重启后的中断任务识别。
- 已成功生成帧的追踪和完整性检查。

不要阻塞 Qt GUI 主线程。

### 帧数据要求

每张抽取的帧必须记录：

- Frame UUID
- Source Media UUID
- 实际 PTS / 时间戳
- 可确定的帧序号
- 输出图片尺寸
- 文件哈希与保存位置
- 抽帧方法及参数
- 生成时间

禁止仅通过 `frame_index / FPS` 推定所有视频的准确时间。

抽帧结果应具有可重复性和明确的采样规则。

## 6. Annotation Workspace — 统一标注工作台

在现有 IVAD GUI 内实现真实可操作的标注界面。

### 6.1 基本界面

建议布局：

- 左侧：项目 / 视频 / 图片列表。
- 中央：当前图片与标注画布。
- 右侧：标注对象属性和类别。
- 底部：图片导航、状态和快捷键。

支持缩放、平移、适应窗口、上一张/下一张。

支持高 DPI 显示。

### 6.2 Bounding Box

支持：

- 鼠标绘制矩形框。
- 移动、缩放、删除。
- 选择故障类别。
- 多目标标注。
- 撤销/重做。
- 自动保存。
- 重新打开后恢复标注。

所有坐标必须以原始图像坐标系保存，而不是屏幕坐标。

### 6.3 Polygon / Mask

支持：

- 鼠标逐点绘制多边形。
- 完成与取消。
- 顶点编辑。
- 移动和删除。
- 类别选择。
- 保存和重新加载。

P2 至少实现基于多边形的实例分割标注。

允许将多边形栅格化成 Mask 用于可视化或导出，但不得强制以有损格式作为唯一的内部真值。

本阶段不要求复杂画笔式像素级修边。

### 6.4 ROI

允许为摄像头或视频配置独立的监控区域。

ROI 与训练目标标注必须作为不同数据类型保存。

支持矩形 ROI 和多边形 ROI。

记录 ROI 与摄像头、项目或视频的关联及版本。

### 6.5 图片与视频片段标签

支持：

- 正常。
- 异常。
- 未知/待确认。
- 用户定义故障类型。

支持对一张图片或指定视频时间段添加标签。

Clip Label 应保存开始时间、结束时间、标签及人工审核状态。

不得把视频片段标签自动转换为单帧 Bounding Box。

### 6.6 标注审核状态

至少包含：

- DRAFT
- REVIEWED
- APPROVED
- REJECTED

支持人工修改和重新审核。

保留修改时间、版本和来源信息。

P2 的人工标注应标记为 Human Generated，未来 P5 的 AI 预标注将使用 Machine Suggested。

不得把未审核 AI 建议标注自动纳入训练真值。

## 7. 故障类型与标签库

实现 GUI 故障标签管理。

支持：

- 新建标签。
- 修改名称与描述。
- 设置所属设备类型。
- 设置父级故障类别。
- 选择默认标注类型。
- 禁用不再使用的标签。

使用稳定 UUID 识别故障类别。

训练导出时再生成连续的 YOLO Class ID。

标签重命名不得改变历史标注对应的内部 UUID。

删除被标注引用的类别前必须进行引用检查，不得造成孤立标签。

建议初始类别仅作为可编辑模板：

- 皮带异物
- 落料口堵煤
- 异常积煤
- 煤流中断
- 未知异常

不得声称以上类别已经存在可用训练模型。

## 8. 数据集管理与版本控制

建立统一 Dataset Manager。

### 核心能力

支持：

1. 从已审核标注中选择图片。
2. 创建数据集。
3. 显示图像及标签统计。
4. 检查图片是否丢失。
5. 检查标注是否合法。
6. 对数据集进行版本冻结。
7. 导出数据集。
8. 重新打开或查询历史版本。

### 数据集划分

支持 Train / Validation / Test。

优先按来源视频、采集时段或摄像头进行分组划分，避免同一视频相邻帧随机落入训练集和测试集。

提供随机划分作为可选策略，但必须提示数据泄漏风险。

训练、验证和测试集不得出现相同文件哈希的重复图片。

检查近重复样本并至少给出警告。

### 版本冻结

每次冻结数据集时记录：

- Dataset UUID
- 版本号
- 来源资产清单
- 图像哈希
- 标注快照
- 类别 UUID 与 Class ID 映射
- 数据集划分
- 创建时间
- 导出格式与校验信息

冻结后的版本必须保持逻辑不可变。

修改标注后应创建新版本，而不是悄悄覆盖旧版本。

## 9. 数据集导出格式

采用内部通用数据格式作为唯一可信主数据。

实现独立 Export Adapter。

### YOLO Detection

导出：

- `images/train`
- `images/val`
- `images/test`
- 对应 `labels/` 目录
- `data.yaml`

遵守标准 YOLO 归一化 Bounding Box 坐标定义。

### YOLO Segmentation

导出多边形实例分割数据。

遵守 Ultralytics Segment 格式。

不能将普通检测框伪装为真实分割 Mask。

### COCO JSON

提供基础 COCO Detection / Segmentation 导出。

若某类标注无法无损导出，应报告限制，不得静默丢弃信息。

### IVAD Native Format

提供包含：

- ROI
- 图片标签
- 视频片段标签
- 标注 UUID
- 版本与审核信息

的原生可追溯导出格式。

### 导出前检查

必须验证：

- 图片文件存在。
- 标签类别映射有效。
- 坐标范围正确。
- 多边形顶点数量及几何有效性。
- 划分结果无重复或明显泄漏。
- YAML/JSON 可解析。
- 目标文件没有被意外覆盖。

不得以创建文件成功代替数据格式正确性验证。

## 11. 计算环境与安全边界

P2 的普通任务，包括视频解码、抽帧、图像浏览、人工标注和数据集导出，允许 CPU 执行。

此前确认的 GPU-only 规则仅针对 AI 模型训练和推理。

本阶段不能因为视频抽帧使用 CPU，就误判违反 GPU-only 规则。

保持：

- GUI `.venv-p1`
- NVIDIA `.venv-nvidia`
- Intel 独立后端接口

不得无理由修改已经通过 P0/P1 的依赖。

若需要安装 FFmpeg、OpenCV 或 Qt Multimedia 相关依赖：

1. 先检查现有环境。
2. 选择可信来源与兼容版本。
3. 记录依赖与安装结果。
4. 不修改系统驱动或其他 AI 环境。

不得擅自安装全局 FFmpeg 或修改系统 PATH；优先采用项目可管理的独立依赖方案。

## 14. 执行权限与工作方法

允许你在 P2 范围内自主编写、测试、修复和更新项目代码。

先做结构检查，再进行增量开发。

优先复用已有 P1 服务和 Qt 组件。

每完成一个主要模块，执行针对性的自动化测试，避免最后集中发现问题。

不要为了缩短输出而跳过必要测试。

不得擅自：

- 删除用户数据。
- 修改系统 GPU 驱动。
- 改动全局 Python。
- 覆盖已有模型或训练环境。
- 开始 P3 正式 AI 训练。
- 开始 P4 工业推理和报警。

## 1. 当前结论

当前交付物是“需求与架构基线 + P0 环境和 GPU 可行性验证工具及证据”，尚不是可操作的 IVAD 桌面软件。

已完成的主要工程工作包括：两套项目专用 Python 环境、固定依赖的可信下载与校验、训练环境离线安装、网络/VPN 排障工具、真实 B390 OpenVINO 基础计算、真实 XPU 前向/反向/参数更新，以及 YOLO11n 的 GPU 推理、OpenVINO 导出和一次合成数据短训。

**YOLO11n 为部分通过：** 最新记录中加载、推理导出基准、短训均 PASS，但独立最小训练探针仍 FAIL。短训成功不能抹去该失败，也不能证明所有训练路径均已支持。

**YOLO26n 仅完成可信权重准备：** 未发现该模型对应的已执行 GPU 推理、训练与基准结果。双模型公平比较没有完成，默认主模型未定。

早期“训练环境只有 pip、XPU 未运行、YOLO 没有性能数据”的正式报告已经过期。依赖下载阻断后来已解除，但最后一批实验结果尚未同步回四份正式验收报告和状态文档。这属于交付与状态维护缺口，不能继续把早期报告当作最新事实。

## 2. 状态定义与证据规则

| 状态 | 本文含义 |
|---|---|
| 已实现 / PASS | 对明确范围已有文件与实际执行证据；不外推至整个产品 |
| 部分实现 / PARTIAL | 有工具、工件或一部分路径通过，但尚有失败、未测路径或未集成部分 |
| FAIL | 确实执行并失败，保留错误与堆栈 |
| 未实现 | 未发现对应应用代码、数据库实现或可操作功能 |
| NOT TESTED | 未发现实际执行结果；写有脚本或下载了文件不算通过 |
| BLOCKED / 未验收 | 存在阻断或验收材料不完整；不代表所有底层能力都失败 |

同一事项发生冲突时，优先核对具体日期的原始日志、结构化结果和工件；旧报告作为历史保留。本文不是重新签署 P0 验收，也不赋予后续阶段开发授权。没有可靠工作量基线，不给出容易误导的整体完成百分比。

### 5.2 YOLO11n 最新推理数据

以第二次实验 [yolo11n.json](raw/yolo11n.json) 与 [attempt2 日志](raw/yolo11n_attempt2_20261014.log) 为当前汇总依据；第一次结果保留于 [attempt1 JSON](raw/yolo11n_attempt1_20261014.json)，两次数据不混算。

| 指标 | 第二次实验结果 |
|---|---|
| 环境 | B390；torch 2.14.1+xpu；Ultralytics 8.4.175；OpenVINO 2026.4.1 |
| 输入与后端 | 同一公开 bus 图片；1×3×640×640；FP32；GPU.0 |
| 方法 | 10 次预热、100 次同步请求；完整原始时延保存在 JSON |
| p50 / p95 | **7.51565 / 8.26310 ms** |
| 请求吞吐折算 | **133.26658 FPS**，1000/平均请求毫秒数 |
| 进程 RSS 采样峰值 | **2,875,179,008 bytes，约 2.68 GiB** |
| 单次解码 / 预处理 | 5.7878 / 4.5008 ms，不能当作稳定分位数 |
| 输出 | `[1,84,8400]`；最终检测数量 5，与参考类别/框在指定容差内一致 |

原始框比较使用 atol=2 像素、rtol=0.01；类别分数使用 atol=0.02、rtol=0.02。最终 NMS 检查数量、类别及框坐标。该容差和单样例不能替代完整验证集精度测试。

133.27 FPS 是模型同步请求口径，**不是录像全流程 FPS、GUI 播放帧率或生产 SLA**；未包含完整解码、预处理、NMS、持久化、事件证据和界面开销。RSS 为采样到的进程工作集，并非显存峰值、全机峰值或严格持续采样峰值。

### 5.3 YOLO11n 短训成功的范围

- 使用本地产生的非敏感合成矩形图：训练 4 张，验证 2 张，单类别。
- 设置：1 epoch、batch=2、640、workers=0、amp=False、mosaic=0、seed=7。
- 使用 `XPUConstructionTrainer`，在 XPU 默认设备上下文内构造模型，避免构造阶段 stride 探测进行 CPU 神经网络前向。
- 训练开始回调核对 trainer 和模型参数在 xpu；日志显示训练、验证完成。
- 生成 `artifacts/p0/runs/yolo11n/weights/last.pt`、`best.pt`、`results.csv` 和 `args.yaml`。
- last.pt SHA256：`c1fb61f8acea9c06e7fd95d58685db73384d4142c9df00d1df83a9ce07a3a0cb`；重载到 XPU，输出有限值，形状 `[1,5,8400]`。

这证明当前适配路径能完成一次短训并产生可重载权重。不是未经适配的原生封装完整兼容证明，也没有进行完整算子 profiler 审计。日志中的合成样本 mAP50≈0.497、mAP50-95≈0.121 仅用于记录实验，不能当作工业精度。验证日志中的 PyTorch 推理耗时与上表 OpenVINO 微基准不是同一测量方法，不直接对比。

### 5.4 仍然失败的最小训练探针

第一次错误为 `'dict' object has no attribute 'box'`；将 `model.args` 转为 `SimpleNamespace` 后，第二次仍报：

```text
AttributeError: 'types.SimpleNamespace' object has no attribute 'box'
ultralytics/utils/loss.py: loss[0] *= self.hyp.box
```

转换容器类型没有补齐损失函数必需的默认超参数，修复不完整。该探针在损失构造/访问参数阶段失败，没有完成自身的 backward/update 断言。不能把它归因为“B390 不支持训练”，也不能因另一路短训成功将它记为 PASS。后续若继续 P0，应单独修正参数构造并保留失败记录；本轮没有执行该修复。

### 7.1 关于网络根因的准确说法

有证据支持：VPN 出口确实影响本次下载路径；出口切换后部分文件显著改善；官方某 CDN 端点独立存在 403；不同源的最佳路径不同。没有足够证据将全部超时归因于 VPN，也没有证据证明 DNS 或证书验证失败是主因。

因此，当前应将“本轮所需依赖恢复”记为成功，将“系统网络全面修复”保持未证实。后续安装不应重复旧地址无限重试，也不应先随意改 Python/PyTorch 版本。

### 7.2 尚未验证的风险，不作为已发生 bug

- 只有一个 epoch、小批量、6 张合成图；大数据、大 batch、长训练、混合精度、内存压力和驱动稳定性未知。
- 未采集可靠的 GPU 利用率、共享内存峰值与持续温度/频率，无法据此规划生产容量。
- YOLO26 受控对照脚本关闭 end2end，未来即使该模式通过，还需测试默认路径。
- 下载/临时出口包装器的整体退出状态与子任务状态仍需统一；恢复守护与子进程树应有专门异常测试，现有代码不等于所有中断场景已验收。
- 没有完整离线禁网测试、全链路遥测审计，也没有证明任意可信权重均不会触发额外下载。
- 未做 GUI/业务单元、集成、端到端、备份恢复、安装卸载测试；当前脚本断言属于 P0 探针。
- 没有真实厂区样本，工业误报率、漏报率、跨录像泛化和事件响应时延尚无法验收。

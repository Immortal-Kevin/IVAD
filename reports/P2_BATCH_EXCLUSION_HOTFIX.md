# P2 批量剔除与工作批次修复

日期：2026-10-15；基线 c79d50d；Schema 0008 保持；PACKAGING_FREEZE = TRUE。

## 根因与实证

原按钮已连接 batch_action，复选框 ID 能传到服务；关键阻断来自 AnnotationService.batch_preview：有目标框/整帧故障类别、已审核或冻结集引用的帧全部禁止剔除。用真实项目一致性副本及历史 c79d50d 服务重放，4 张有标注/审核图片全部被跳过（selected=4，eligible=0，skipped=4）。旧 GUI 在全拒绝时不弹结果窗口，仅写底部 info，容易与当前帧载入信息混淆。该路径已复现；没有截图推断现场每次点击都来自同一原因。

## 实现与语义

- 单帧和“批量剔除无效帧”设置 handling.is_excluded，不删除帧文件、目标、整帧标签、审核或修订。已有标注或冻结引用不再阻止安全软剔除；冻结 manifest 和旧样本不重写，新数据集排除 EXCLUDED。
- 预览显示已选/可处理/已有人工标注/冻结引用/跳过及原因；全跳过有结果弹窗。独立左侧 batch_result 保留结果，刷新或当前帧切换不会覆盖。
- 完成后报告成功 X、跳过 Y、失败 Z；错误显示整批未提交。事务内复核标注修订、处理修订及摄像头 ID，发生冲突整批回滚。
- 日志在提交后失败时如实提示“已提交但日志失败”，不谎称回滚。
- “从当前批次移除”仅设置 handling.worklist_hidden，不改变剔除状态、内容或训练资格。默认“当前工作批次”隐藏它；选择“全部帧（含已移出）”或“仅已移出批次”，用“移回当前批次”恢复显示。
- 当前架构采用每项目一个默认工作列表，不新增命名批次/多操作员成员表。此限制明确告知，未重构媒体数据库。剔除和工作列表移除互相独立，均无永久物理删除入口。
- 摄像头筛选切换清除勾选；批量 ID 与当前可见集合求交。多来源摄像头混选默认拒绝；勾选独立“允许跨摄像头批量操作”入口后，还需跨摄像头确认和操作预览确认。预览期间筛选/项目变化则取消。

## 验证

同摄像头两张正常/异常图通过真实 Qt 勾选→剔除→恢复；已有目标和审核原样保留；冻结 manifest 字节不变；全部拒绝弹窗；切换摄像头隐藏选择清除；跨摄像头默认拒绝；移出/移回均通过。既有批量中途故障注入仍验证整批回滚。
